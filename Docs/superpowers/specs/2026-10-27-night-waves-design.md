# 밤 웨이브 개편 — 설계 문서

> 작성: 2026-10-27 · 수정: 2026-10-29 · 상태: **승인됨 (2026-10-29)** · 빌더 체크 반영 완료
> 기준 문서: `Docs/Cute_Carnage_GDD_2.0V.md`, `CLAUDE.md`. 충돌하면 그쪽이 우선이다.
> 표시: **[사용자 결정]** = 사용자가 정함 · **[Claude 판단]** = 대화에서 Claude가 정했고 사용자가 이의 없음 · 표시 없음 = 기존 확정 사항.

## 1. 왜 바꾸는가

지금 밤은 "웨이브 1 → 전멸할 때까지 대기 → 웨이브 2 → …" 구조라서 웨이브 사이가 비고 끊긴다. 7일 내내 같은 종류의 좀비만 나와서 "오늘 밤은 다르다"는 느낌도 없다.

목표 장면 **[사용자 결정]**: 밤이 깊어질수록 몇십~몇백 마리의 좀비가 땅에서 기어 나와 기지로 몰려오고, 타워들이 피와 폭발 속에서 그 대군을 쓸어낸다. 플레이어는 자동공격으로 싸우며 돌아다니다가 **방어선이 무너지는 곳으로 달려가서 막는 "소방수"** 역할을 한다. 그래서 웨이브 설계의 핵심은 **여기저기서 방어선이 흔들리는 순간을 만드는 것**이다.

## 2. 목표 / 비목표 / 실패 조건

**목표**
- 밤 내내 좀비가 끊기지 않고 오다가, 정해진 **시간**에 큰 무리가 몰려오는 흐름.
- 밤마다 새로운 요소 하나씩: 무리, 러너, 펜스브레이커, 탱커, 보스.
- 좀비가 땅에서 기어 나오는 등장 연출.
- 화면 밖 상황을 알려 주는 HUD (무리 접근 `!`, 피격 방향 빨간 표시, 시간 기반 달 다이얼).
- 동시에 **최소 몇백 마리**가 살아 있어도 끊기지 않는 성능.

**비목표 (이번 작업에서 안 함)**
- 타워 업그레이드/새 타워 (기관총, 발리스타 등) — 별도 설계.
- 카메라 줌, 홈베이스 축소, 캐릭터·좀비 가독성(아웃라인 등), 기지 안개 제거 — 별도 작업.
- 피·폭발 VFX, 사운드 — 별도 작업. 단, 등장 연출의 땅 솟음·먼지 이펙트는 이번 범위.
- 보스 전용 외형 — 사용자가 나중에 직접 제작. 그전엔 임시 모델.
- 보스의 추가 패턴 (원거리 토하기 웅덩이 등) — 나중에.

**실패 조건 (기술적으로 돌아가도 실패)**
- 밤이 타이머로 끝나는 것. (CLAUDE.md 규칙 7 위반)
- 몇백 마리에서 1초마다 멈칫하는 끊김. (현재 상태 — §8 참고)
- 웨이브가 와도 플레이어가 화면 밖 상황을 전혀 모르는 것.
- 사방에서 고르게만 와서 타워만으로 다 막히고 플레이어가 할 일이 없는 것.

## 3. 지켜야 할 제약

- **밤 종료 규칙 (규칙 7):** 마지막 웨이브 포인트까지 전부 스폰되고, 그날 밤 스폰된 좀비(보스 포함)가 전부 죽어야 밤이 끝난다. `SimpleZombieSpawner`가 Day 전환을 요청하는 유일한 주체로 남는다. 시간으로 밤을 끝내는 코드를 넣지 않는다. GameOver → Retry 경로는 기존 그대로.
- **규칙 6 (폴링 금지):** HUD는 값이 바뀔 때만 갱신한다. 다만 시간 기반 다이얼과 화면 가장자리 인디케이터는 본질적으로 매 프레임 위치가 바뀌는 표시라서, `DayNightClouds`처럼 **표시 전용 애니메이션 예외**로 둔다 (상태 판단은 이벤트로, 위치/진행 표시만 프레임 단위). 예외임을 코드 주석에 남긴다.
- **GDD 승인 사항 보존:** 밤 HUD의 "달 다이얼 + 엘리트/보스/큰 웨이브 이벤트 마커" 방향을 따른다. 기존 다이얼 아트(`Art/UI/HUD/DayNightTiner/`)는 그대로 쓴다.
- **저장:** 밤 진행 상태는 저장하지 않는다 (저장은 Day 시작 체크포인트뿐). Retry는 그 Day로 돌아가므로 밤 중간 상태 복원은 필요 없다.
- **PersistentId / 슬롯 구조:** 건드리지 않는다.

## 4. 밤 구조 **[사용자 결정]**

```
좀비 수
  ^                                   ___
  |                     ___          |   |   ← 웨이브 3 (가장 큼)
  |         ___        |   |         |   |
  |        |   |       |   |         |   |
  |  ______|   |_______|   |_________|   |____ ← 기본 흐름(스트림)
  +--------------------------------------------> 시간
          웨이브1      웨이브2      웨이브3   (이후 남은 좀비 정리 → 아침)
```

**목표 감각 [사용자 결정, 2026-10-29]:** 밤은 **쉬지 않고 몰아치는 약 5분 전투**다. 좀비는 끊기지 않고 오며 시간이 갈수록 많아진다. 웨이브는 "플레이어가 넘겨야 하는 위험한 순간"이고, 그때 플레이어는 더 열심히 움직이고·수리하고·싸워야 한다.

- **전투 시작:** 밤이 시작되고 **5~10초 안에** 좀비가 기지에 닿아 전투가 시작된다 **[사용자 결정]**.
- **기본 흐름(스트림):** 밤 시작부터 마지막 웨이브 포인트가 끝날 때까지 좀비가 끊기지 않고 나온다. **스폰 간격이 시간이 갈수록 짧아진다** (밤 후반일수록 많아짐) **[사용자 결정]**.
  - 스폰 위치: 기지 중심 기준 **반경 링(min~max) 안 360도 무작위** — 펜스 바깥 가까운 곳부터 화면 밖 먼 곳까지. 반경은 사용자가 에디터에서 정한다 (기존 `minSpawnRadius`/`maxSpawnRadius` 사용) **[사용자 결정]**.
  - 가까이서 나온 좀비는 §7 등장 연출로 땅에서 나와 자연스럽게 보이고, 멀리서 나온 좀비는 천천히 걸어온다.
- **웨이브 포인트:** 정해진 **시간**에 큰 무리가 **멀리서**(화면 밖) 나와 몰려온다. 가까이서 스폰하지 않는다 **[사용자 결정]**. 앞 웨이브를 다 못 잡았어도 다음 웨이브는 온다 (겹침 허용 — 이게 방어선 붕괴의 긴장감).
- **웨이브 후 숨 돌리기 [사용자 결정]:** 한 웨이브 무리의 **80%가 처치**되면 **10초 동안 스트림이 평소의 30%로 줄어든다**. 멈추는 게 아니라 줄이기만 한다. 웨이브 일정(다음 웨이브 시각)에는 영향을 주지 않는다 — 80%를 못 잡은 채 다음 웨이브가 오면 숨 돌리기는 없다 **[Claude 판단]**.
- **스폰 자리 바닥 확인 [사용자 결정]:** 스폰 후보 자리마다 아래로 레이를 쏴서 지형 위인지, 그 자리에 바위·건물·펜스 등 콜라이더가 겹치지 않는지 확인한다. 실패하면 몇 번 다른 자리를 고르고, 그래도 실패하면 다음 스폰 때 다시 시도한다 (스폰 수는 줄지 않음 — 밤 종료 규칙 보호).
- **웨이브 시각 정하는 법 [사용자 결정, 2026-10-29]:** 웨이브마다 **"앞 웨이브 시작부터 이 웨이브까지 몇 초"**를 적는다. 첫 웨이브는 밤 시작 기준이다.
  예: 웨이브1 `20초` → 웨이브2 `40초` → 웨이브3 `60초`이면 밤 시작 20초에 웨이브1, 60초에 웨이브2, 120초에 웨이브3.
  - 위 예시 숫자는 설명용이다. 실제 값은 "5분 전투" 기준으로 빌더가 초안을 잡는다 (마지막 웨이브 ≈ 4분 30초 전후).
  - 밤 시작 ~ 웨이브1 전: 스트림만으로 전투.
  - 웨이브1 시각이 되면 스트림과 함께 웨이브1 스폰이 시작되고, **동시에** 웨이브2까지의 시간이 흐르기 시작한다 (웨이브1 스폰이 끝나거나 처치될 때까지 기다리지 않음).
  - 웨이브2 시각이 되면 바로 웨이브2, 이어서 웨이브3까지 시간이 흐른다. 마지막 웨이브까지 같은 방식.
  - 타이머와 다이얼 게이지는 밤 시작부터 마지막 웨이브까지 **멈추거나 리셋되지 않고** 이어서 흐른다.
- **웨이브 하나의 구성:** 어떤 좀비를 몇 마리, 어느 방향(사방 또는 동서남북 중 하나 + 퍼짐 각도), 몇 초 간격으로.
- 마지막 웨이브 포인트의 스폰이 끝나면 스트림도 멈춘다. 이후 남은 좀비를 전부 잡으면 아침.
- 방향은 기존 `NightSchedule.Compass`(북=숲, 동=공장, 남=마을, 서=쇼핑몰, +Z가 북)를 그대로 쓴다.

**데이터 [Claude 판단]:** 기존 `NightSchedule` ScriptableObject를 새 구조로 바꾼다. 밤마다 `스트림(간격, 사용할 좀비 종류)` + `웨이브 포인트 목록(앞 웨이브부터의 대기 초, 구성 목록, 방향, 퍼짐, 간격)` (실제 시각 = 대기 초의 누적 합, 런타임에 계산). 하나의 웨이브 포인트 안에 여러 구성(예: 사방 기본 20 + 북쪽 무리 30)을 넣을 수 있어야 한다. 기존 `Horde`의 "한 방향 + arc" 개념은 그대로 살린다. 현재 `NightSchedule.asset`의 수치는 테스트 값이므로 새 구조로 옮길 때 보존하지 않고 §6 표 기준으로 새로 채운다.

## 5. 좀비 종류

기존 `ZombieData`(종류, 우선 대상 필드는 이미 있으나 **현재 코드에서 안 쓰임**)를 실제로 쓰게 만든다. 스포너는 지금 프리팹 하나만 받으므로, 종류별 프리팹/데이터를 받을 수 있게 바꾼다.

| 종류 | 첫 등장 | 역할 | 행동 |
|---|---|---|---|
| Basic | 1일 | 기준 | 현재 동작. 이동속도 0.65 → **1.3m/s** (플레이어 5m/s보다 확실히 느리게) **[사용자 결정, 2026-10-29, 데이터 반영됨]** |
| Runner (화면 이름: 점프형) | 3일 **[Claude 판단]** | 플레이어를 뛰게 만듦, 방어선 안쪽을 흔듦 | L4D처럼 **점프로 이동**한다. 붙잡기 없음 **[사용자 결정]**. 아래 참고 |
| Breaker | 4일 **[Claude 판단]** | 펜스를 빨리 뚫음 | 보통 속도, 펜스 데미지 큼. **각자 직선 이동 중 만난 펜스를 공격**한다 **[사용자 결정]** — 무리가 한 펜스를 골라 모이는 그룹 로직은 넣지 않음 |
| Tank | 5일 **[사용자 결정]** | 타워 화력을 오래 묶음 | 느리고 체력 아주 많음. 앞에 있는 것부터 공격 |
| Boss | 7일 **[사용자 결정]** | 최종 보스 | 아래 참고 |

**점프형 (Runner) [사용자 결정, 2026-10-29]:** 우선순위 순서로 판단한다.
1. 사정거리 안에 **플레이어**가 있으면 → 플레이어에게 점프해서 **1회 공격**(할퀴기/물어뜯기) → 쿨다운(초안 3초, 그동안 걸어서 따라옴) → 다시 점프 공격.
2. 사정거리 안에 **타워**가 있으면 → **펜스를 뛰어넘어** 타워 앞에 착지 → 제자리에서 할퀴기 공격 반복.
3. 둘 다 없으면 → 점프를 반복하며 베이스 쪽으로 다가온다.
- 점프 전 짧은 웅크림 예고(초안 0.5초)를 넣는다 — 탑다운 화면에서 읽고 대응할 틈 **[Claude 판단]**.
- 점프 중에는 펜스 충돌을 무시하고 포물선으로 이동, 착지 자리는 스폰과 같은 바닥 확인을 한다 **[Claude 판단]**.
- 코드의 `ZombieType.Runner` 값은 데이터·저장과 묶여 있으므로 이름을 바꾸지 않고, 화면에 보이는 이름만 바꾼다 **[Claude 판단]**.
- 필요한 애니메이션: 점프(도약)·착지 — **사용자가 Mixamo에서 받을 것.** 할퀴기는 기존 `zombie attack` 사용 가능.

**체력 증가 [사용자 결정, 2026-10-29]:** 좀비 체력은 **날마다** 배율로 오른다 (초안 +15%/일, 플레이테스트로 조정). 한 밤 안에서는 체력을 올리지 않고, **마릿수와 강한 종류(브레이커·탱커)의 비율**을 올린다 — 같은 좀비가 갑자기 안 죽는 "총알 스펀지" 느낌을 피하기 위해.

**보스 [사용자 결정]:**
- 원거리 토하기 공격 — 사거리 안의 펜스·타워·플레이어 중 하나에 투사체. 바닥 웅덩이 없음 **[Claude 판단]**.
- 느리지만 강력한 근접 공격 — 펜스를 몇 번에 부수는 수준.
- 아주 많은 체력 — 타워 여러 개와 플레이어가 같이 집중해야 잡히는 수준.
- 7일차 마지막 웨이브와 함께 등장. 보스까지 죽어야 밤(=게임)이 끝난다 → 기존 Victory 흐름으로 이어짐.
- 외형은 기본 좀비를 크게 키운 임시 모델 **[Claude 판단]**. 사용자가 나중에 교체.

구체 수치(HP, 속도, 데미지)는 빌더가 초안을 잡고 플레이테스트로 맞춘다.

## 6. 7일 흐름 **[사용자 결정: Claude 추천안 채택]**

| 밤 | 새로 느끼는 것 | 웨이브 포인트 |
|---|---|---|
| 1 | 기본 좀비만. 스트림 + 작은 웨이브로 규칙 익히기 | 2개, 사방 |
| 2 | 처음으로 **한 방향 무리** | 2개, 하나는 한 방향 |
| 3 | **점프형(Runner)** 등장 | 3개 |
| 4 | **펜스브레이커** 등장, 무리에 섞임 | 3개 |
| 5 | **탱커** 등장, 마지막 웨이브에 | 3개 |
| 6 | 전부 섞임, 두 방향 동시 무리 | 3개, 가장 큼 |
| 7 | **보스**, 마지막 웨이브와 함께 | 3개 + 보스 |

마리 수·간격·웨이브 시각은 빌더가 초안을 잡는다. 7일차 마지막 웨이브에서 **동시 생존 수백 마리**가 나오는 규모를 목표로 한다 **[사용자 결정]**.

## 7. 등장 연출 — 땅에서 기어 나오기

**순서 [사용자 결정]:**
1. 땅 조각이 위로 솟아오르며 먼지가 피어오르는 이펙트 (나올 자리 예고) **[사용자 결정, 2026-10-29 — 땅 갈라짐 대신]**.
   - 방식 **[Claude 판단]:** Terrain 자체를 변형하지 않는다 (높이맵 수정은 느리고 Terrain 에셋에 영구 반영됨). 대신 흙·돌 조각 메시를 파티클(Mesh 렌더 모드)로 땅 밑에서 튀어 올렸다가 내려앉히고, 같은 자리에 먼지 파티클을 함께 터뜨린다. 조각 색은 흙바닥(`TL_Dirt`) 톤에 맞춘다.
   - 수백 마리가 나오므로 이펙트도 풀링해서 재사용한다 (좀비 풀링과 같은 원칙).
2. 애니메이션 재생: 땅에 엎드린 자세에서 팔을 뻗어 땅을 긁고 → 몸을 끌어올리고 → 웅크렸다가 → 비틀거리며 일어선다. 앞부분은 좀비를 땅 밑에 살짝 묻어 두고 위로 끌어올리면서 재생한다.
3. 걷기 시작해서 홈베이스로.

**애니메이션 소스:** 사용자가 Mixamo에서 받은 "엎드림 → 일어서기" 동작 (228프레임, 약 7.6초 @30fps) — `Assets/Animations/ZombiePack/Getting Up.fbx`로 들어옴 (2026-10-29). Humanoid 설정과 클립 자르기는 빌더가 한다.
- 길이 **[Claude 판단]:** 끝에 가만히 서 있는 부분(약 170프레임 이후)은 자르고, 1.5~2배 속도로 재생해서 **3~4초**. 최종값은 게임 안에서 보면서 조정.
- 등장 연출은 나중에 동작을 바꾸기 쉽게 별도 단계로 분리한다.
- **화면 안에서 스폰될 때만** 땅 솟음 이펙트 + 일어서기 애니메이션을 재생한다. 화면 밖이면 바로 걷기로 시작한다 **[사용자 결정]**. 화면 안 판정은 스폰 순간 한 번만 한다 (나중에 카메라가 비춰도 다시 재생하지 않음) **[Claude 판단]**.
- 등장하는 동안(이펙트·애니메이션이 끝날 때까지) **이동·공격 불가** **[사용자 결정]**. 등장 중에도 **공격받을 수는 있다** **[Claude 판단]** — 타워가 나오자마자 맞히는 장면.
- 등장 중인 좀비도 스폰 시점부터 `AliveZombieCount`에 포함된다 (밤 종료 규칙 보호).
- 등장 연출을 쓰는 건 **스트림 좀비뿐**이다. 웨이브 무리·탱커·보스는 멀리(화면 밖)에서 나와 걸어오므로 연출 없음. 탱커·보스 전용 등장 연출은 **나중으로 미룬다** **[사용자 결정]**.
- 걷기 애니메이션 재생 속도를 이동속도에 맞춰 조정한다 — 지금은 Animator `Speed`가 0/1만 받아서 속도를 올리면 발이 미끄러진다 **[Claude 판단]**.

## 8. 성능 — 동시 수백 마리

**측정 (2026-10-27, 에디터 Play Mode, 좀비가 기지로 걸어오는 상태):**

| 좀비 수 | 평균 프레임 | 상위 5% |
|---|---|---|
| 0 | 6ms | 7ms |
| 300 | 16ms | 56ms |
| 500 | 29ms | 91ms |

**원인 (확인됨):** `Zombie.SelectFrontTarget()`의 앞 감지 캡슐(`forwardDetectMask`가 Default 포함)이 매번 **Terrain**에 걸리고, `TerrainCollider.ClosestPoint()`가 좀비당 약 0.3ms로 감지 시간의 92%를 차지. 또 같은 프레임에 스폰된 좀비들의 `targetRefreshTimer`가 전부 같아서 **1초에 한 번 몰아서** 실행됨.

**두 원인만 임시로 없앤 결과:** 300마리 평균 14ms / 상위 5% 15ms, 500마리 평균 17ms / 상위 5% 19ms. 남은 시간은 대부분 렌더링·애니메이션이고 좀비 로직은 약 3ms.

**이번 작업에 포함할 성능 정리:**
1. 앞 감지에서 Terrain 제외 (또는 관련 컴포넌트가 있는 콜라이더에만 `ClosestPoint` 호출).
2. `targetRefreshTimer` 초기값을 무작위로 흩뜨림.
3. `PlayerAutoCombat`의 `FindObjectsByType<Zombie>` 반복 검색을 좀비 목록 한 곳 관리로 교체.
4. 좀비 재사용(풀링) — 죽은 좀비를 5초 뒤 `Destroy`하고 새로 `Instantiate`하는 대신 재사용. Retry가 좀비를 정리하는 경로, `AliveZombieCount` 증감(`OnEnable`/`OnDisable`/`OnDestroy`/`Die`)과 반드시 맞물려야 한다.
5. 화면 밖 좀비 애니메이터 컬링.

**목표:** 동시 500마리, 타워·플레이어가 싸우는 실제 전투에서 에디터 상위 5% 프레임 25ms 이하. (전투 중 측정은 아직 안 함 — 구현 후 같은 방식으로 측정한다.)

**목표 미달 시 [사용자 결정]:** 이번 작업에서 GPU 애니메이션 굽기·DOTS로 파고들지 않는다. 대신 동시 생존 상한과 §6 마리 수를 줄여서(예: 300) 진행하고, 큰 렌더링 작업은 나중에 별도로 한다. 측정 결과와 정한 상한은 이 문서에 기록한다.

**동시 생존 상한 [사용자 결정]:** 스포너는 살아 있는 좀비 수가 상한(기본 500, 위 측정 결과에 맞춰 조정)에 닿으면 처치로 자리가 날 때까지 다음 스폰을 미룬다. 미룬 좀비도 그날 밤 반드시 스폰되고, 밤 종료 규칙(전부 스폰 + 전부 처치)은 그대로다. 그래서 웨이브 포인트의 실제 스폰이 예정 시각보다 늦어질 수 있다 — 다이얼은 예정 시각 기준으로 진행하고, 밀린 스폰은 마지막 웨이브 이후 "남은 좀비" 단계에서 자연히 처리된다 **[Claude 판단]**.

## 9. HUD

**달 다이얼 [사용자 결정: 시간 기반]:**
- 밤 진행도 = 밤 시작부터 경과 시간 ÷ 마지막 웨이브 포인트 시각(대기 초의 합). 지금의 "웨이브 번호 + 처치 수" 공식을 대체한다. 게이지는 웨이브 사이에서 멈추거나 리셋되지 않는다 **[사용자 결정]**.
- 상세 텍스트에 **다음 웨이브까지 남은 초**를 보여 준다 (예: `WAVE 2 · 0:34`). 웨이브가 시작되면 곧바로 다음 웨이브까지의 남은 시간으로 바뀐다 **[Claude 판단]**.
- 웨이브 포인트 시각마다 다이얼 바에 마커 (기존 `waveDividerTemplate` 활용, GDD 승인 방향). 보스/탱커가 나오는 웨이브는 다른 마커 **[Claude 판단]**.
- 마지막 웨이브 이후 진행도는 가득 찬 상태로 두고, 상세 텍스트에 남은 좀비 수를 보여 준다 **[Claude 판단]**.

**웨이브 알림은 두 단계 [사용자 결정, 2026-10-29]:**
1. **다이얼 마커 = 웨이브 시작.** 웨이브 시각에 다이얼 마커를 지나며 웨이브가 출발했음을 알린다.
2. **베이스 둘레 알람 = 무리 접근.** 베이스 둘레에 원형 트리거 콜라이더(반경은 에디터에서 조정, `HomeFogZone`과 같은 방식)를 둔다. 웨이브 무리 좀비가 여기에 닿으면 **알람 이벤트**가 발생하고, 무리가 온 **방향에 맞춰 화면 가장자리에 느낌표 `!`(Screen Space UI)**를 띄운다. 도착 예상 시각 계산은 쓰지 않는다.
   - 스트림 좀비는 계속 둘레를 지나가므로 **웨이브 무리 소속 좀비만** 센다. 무리마다 **한 번만** 울린다 **[Claude 판단]**.
   - 울리는 기준: 맨 앞 한 마리가 아니라 그 무리의 몇 마리(초안 5마리)가 들어왔을 때 — 낙오자 한 마리로 울리지 않게 **[Claude 판단]**.
   - 사라지는 시점: 무리가 화면 안에 들어오거나 80% 처치될 때 **[Claude 판단]**.
   - 판정은 트리거 진입 이벤트로만 한다 (매 프레임 거리 계산 없음, 규칙 6). `!` 위치 갱신만 표시 전용 예외.

**피격 방향 빨간 인디케이터 [사용자 결정]:**
- 펜스나 타워가 공격받으면 그 방향을 화면 가장자리 빨간 표시로 알려 준다. 방향만, 구체 정보 없음.
- 그 구조물이 화면 안에 보이면 표시하지 않는다 **[Claude 판단]**.
- 같은 구조물이 계속 맞으면 표시를 유지하고, 일정 시간 안 맞으면 사라진다 **[Claude 판단]**.
